# WebRTC TURN Setup

Hope Hub uses Socket.IO for WebRTC signaling and coturn for TURN relay support.

## Production TURN Server

- DNS: `turn.hopehub.in`
- Public IP: `13.233.107.251`
- TURN URL exposed to apps: `turn:turn.hopehub.in:3478`
- Realm: `hopehub.in`
- Server package: `coturn`
- Service: `coturn`

For the current MVP, TURN can run on the existing production server. Later, move the same
DNS/env values to a separate TURN instance without changing the apps.

Preferred setup uses temporary TURN credentials generated by the API. Store only the shared
secret on the production server:

```bash
/etc/hopehub-turn-url
/etc/hopehub-turn-urls              # optional comma-separated list, e.g. turn + turns
/etc/hopehub-turn-shared-secret     # preferred for short-lived credentials
/etc/hopehub-turn-username-prefix   # optional, defaults to hopehub
/etc/hopehub-turn-ttl-seconds       # optional, defaults to 3600
```

Static credentials are still supported as fallback:

```bash
/etc/hopehub-turn-username
/etc/hopehub-turn-credential
```

The API reads these into `apps/api/.env` during local production deploy through:

```bash
deploy/scripts/deploy-api-local.sh
```

## Required Firewall Ports

Lightsail instance `Ubuntu-1` must allow the TURN listener and relay range. For MVP, keep
the relay range small:

```text
3478/tcp
3478/udp
50000-50100/udp
```

Ports `22/tcp`, `80/tcp`, and `443/tcp` remain required for SSH and web/API traffic.

## coturn Config

Main config file:

```bash
/etc/turnserver.conf
```

Important settings:

```conf
listening-port=3478
fingerprint
lt-cred-mech
realm=hopehub.in
server-name=turn.hopehub.in
external-ip=13.233.107.251/172.26.3.37
use-auth-secret
static-auth-secret=<stored-shared-secret>
no-cli
no-multicast-peers
no-loopback-peers
min-port=50000
max-port=50100
```

`external-ip` is required because the Lightsail public IP is NATed to the instance private IP.

## API Endpoint

Authenticated clients load ICE servers from:

```text
GET /rtc/ice-servers
```

Expected shape:

```json
{
  "iceServers": [
    { "urls": "stun:stun.l.google.com:19302" },
    { "urls": "stun:stun1.l.google.com:19302" },
    {
      "urls": ["turn:turn.hopehub.in:3478"],
      "username": "1790000000:hopehub",
      "credential": "***"
    }
  ]
}
```

If `TURN_SHARED_SECRET` is configured, the API returns temporary HMAC credentials. If not,
it falls back to `TURN_USERNAME` + `TURN_CREDENTIAL`.

## Current-server MVP Config

On the existing server, install coturn and keep the relay port range small at first:

```conf
listening-port=3478
fingerprint
lt-cred-mech
use-auth-secret
static-auth-secret=<same value as /etc/hopehub-turn-shared-secret>
realm=hopehub.in
server-name=turn.hopehub.in
external-ip=<public-ip>/<private-ip>
no-cli
no-multicast-peers
no-loopback-peers
min-port=50000
max-port=50100
```

Open only:

```text
3478/tcp
3478/udp
50000-50100/udp
```

This is enough for early testing. If calls grow, move TURN to a separate server and widen
the relay port range.

## Verification

Check DNS:

```bash
nslookup turn.hopehub.in
```

Check coturn:

```bash
sudo systemctl status coturn
sudo ss -lunpt | grep :3478
```

Check API:

```bash
curl -H "Authorization: Bearer <token>" https://api.hopehub.in/rtc/ice-servers
```

The returned TURN username should look like `<unix-expiry>:hopehub` when temporary
credentials are active.

## App Integration

The shared call UI lives in:

```text
libs/platform-ui/src/consultation-call
```

Current consumers:

```text
apps/user-web
apps/doctor-web
apps/healing-web
```

Calls require:

- an authenticated Socket.IO connection to the API
- the consultation id
- the target user id
- ICE servers from `/rtc/ice-servers`
- a consultation with an assigned doctor for patient-side calling
